## 0. 怎么读这份规范

### 0.1 证据优先级（冲突时按此裁决）

1. **平台安全红线**（`docs/research/platform.md` §11/§12，下称 **P**）——只写 app 槽与 `/sdcard/mp`、不写 NVS/分区表/otadata（除 recovery）、**BLE 名与日志不含 MAC/SN/efuse**、面板未就绪时拒绝而不是"画一页"。这一层高于下面所有层：任何视觉/行为理由都不能推翻它。
2. **原厂固件 1.3.739 的视觉**（`docs/research/stock_ui.md`，下称 **S**）——分区、栅格、字号梯度、选中横线、键帽图标、文案语气。
3. **Miaopaper 的行为与协议**（`docs/research/miaopaper.md`，下称 **M**）——状态机、页边界算法、按键手势、BLE 字节布局、存储语义。
4. **平台组件的真实行为**（P 的其余部分）——`display` 的 5 s 间隔/失败升级、`input` 的事件模型、`storage` 的挂载语义。
5. 本规范的**决策**（标 `【D#】`）——只在前四者留白处使用，每条都写明"为什么"。

正文里 `S §x`/`M §x`/`P §x` 指对应研究文档的章节；`ebook.c:NN` 指 `refs/Miaopaper/Firmware/src/` 的行号。

### 0.2 三条不可谈判的硬约束

- **屏幕文字里不出现 `MENU`/`OK`/`FUNC`/`PREV`/`NEXT`/`F`/`L`/`R`**。键名一律用键帽图标（§1.7）。
- **页边界必须与 Miaopaper 逐字节一致**（§4）。分页是协议的一部分（主机按同样的算法算"上一页"和进度）。
- **只写 `/sdcard/mp`**；不写 NVS、不写分区表、不写 bootloader；otadata 只有 `recovery_*` 能写（§8）。
- **不出示身份**：广播名固定 `MPP_E2S`，广播 Service Data 的 MAC 字段填 0；日志与屏幕都不出现 MAC/SN/efuse/NVS 内容（P §11#5、§12#43）。
- **面板未就绪就拒绝**：`display_ready()==false` 时 `display_post()` 会静默丢帧（`display.c:367`），所以任何"必须先看到屏幕才能继续"的流程（恢复原厂）在该状态下**直接拒绝并只写日志**，不显示任何页面。

#### 1.5.6 锁屏

- **有锁图**（`mp_store_lock_valid()`）：整屏就是图。锁图是 4000 B 的 `epd_temp` 布局（`idx=(y>>3)*250+x`，`bit(y&7)=1` 为黑，128 行）。显示时**从第 6 行开始**：
  ```
  for y in 0..121:  for x in 0..249:
      src = img[((y+6)>>3)*250 + x] & (1 << ((y+6)&7));
      gfx_px(fb, x, y, src ? 1 : 0);   /* 锁图 bit=1 是黑；gfx_px(black=1) 把帧 bit 清 0 */
  ```
  **极性**：锁图与帧的"1"含义相反（图 1=黑，帧 1=白），但 `gfx_px(fb,x,y,1)` 本身就画黑——所以**直接把 src 传给 black 参数**，不要写 `src?0:1`（那是把图反相，整屏会变成黑底白线）。
  不叠任何文字、不加白条（M `ebook.c:953-963` 明确去掉了 overlay）。
- **无锁图**：兜底页 = 锁图标 16×16 **实心剪影 + 白锁孔** @`(MP_LOCK_ICON_X, MP_LOCK_ICON_Y)`=(117,30) +
  `已锁定`（居中 x=101，行顶 `MP_LOCK_TEXT_TOP`=56）+ 一组 `长按[○]解锁`
  （x=`MP_LOCK_HINT_X`=84，y=`MP_LOCK_HINT_TOP`=105，82 px）。**唯一真源是 `mp_ui.h` 的常量**；
  不写英文、不写长句。
- 锁屏一律**场景全刷**（§5）。

## 2. 按键

### 2.1 物理键与事件（平台事实）

| 逻辑键 | GPIO | 置信度 | 事件 |
|---|---|---|---|
| PREV | 2 | 推断 | DOWN / CLICK / LONG / REPEAT |
| NEXT | 4 | 推断 | 同上 |
| MENU | 7 | **真机实测** | DOWN / CLICK / LONG（无 REPEAT） |
| OK | 8 | **真机实测** | 同上 |
| FUNC | 6 | 推断（原 MENU 位） | 同上 |

- 低有效；`input_init()` 开内部上拉（`input_keys.c:274-288`）。
- 20 ms 轮询、60 ms 去抖、`READER_KEY_LONG_MS=1000`（`e2s_mp/CMakeLists.txt:13` 已生效，P §4.3）。
- **没有双击**（`input.h:20-25` 只有 4 个事件）；双击必须在 app 层合成（§2.3）。
- 队列 32 条；app 必须及时消费，一次 >20 ms 的卡顿可能丢非翻页键（P §4.5）。
- **五键都只在 `CLICK` / `LONG` 上动作**（Miaopaper 的模型：松开才翻页/确认，`ebook_buttons.c:143-164`）：
  - `KEY_EV_DOWN` **不产生任何动作**，只用来取消 pending 状态（例如按住 OK 时把待发的单击作废）。
  - `KEY_EV_REPEAT` **一律忽略**。`input` 只在 LONG 之后才发 REPEAT（`input_keys.c:248-253`），而本规范给每个键的 LONG 都定义了动作（§2.4），REPEAT 再翻页会与"按住 NEXT 退出阅读"打架。快速翻页 = 连按（Miaopaper 也没有连发）。
  - `input_inject()` 对 PREV/NEXT 注入的是 DOWN（`input.h:43-48`），因此**不能**用它驱动本状态机；app 层自测请直接调 `mp_app_key(id, KEY_EV_CLICK, now_ms)`。

### 2.2 时序（冻结，与 M §3.1 一致）

| 参数 | 值 | 说明 |
|---|---|---|
| 短按 | 按下 → 松开 < 1000 ms | 松开时 `KEY_EV_CLICK`；PREV/NEXT/OK/MENU/FUNC 全部在 CLICK 上动作 |
| 长按 | 1.0 s（去抖后起算，物理约 1.06 s） | 每个按下只发一次 LONG；LONG 之后松手**不再发 CLICK**（`input_keys.c:226-247`） |
| 双击窗口 | **350 ms** | 只对 OK、只在 READ 生效（§2.3） |
| 连发 | 不使用 | 见 §2.1；`KEY_EV_REPEAT` 丢弃 |

### 2.3 OK 的 350 ms 多击门（全局，复刻 lwbtn）

`input` 每按一次只发一个 CLICK，没有多击计数（`input.h:20-25`）。为了既不误触、又能识别
"双击=上一页"，**OK 的 CLICK 在所有屏上都延迟 350 ms**（Miaopaper 的 `lwbtn` 也是这个行为，
M §3.2）：

```
状态：pending_ok, pending_ok_ms        // 没有 pending_screen：切屏一律取消
收到 OK CLICK：
    if (pending_ok && now-pending_ok_ms <= 350) {
        pending_ok = 0;                       // 双击
        if (screen == READ) 上一页();         // 唯一有双击语义的屏
        // 其它屏：双击=无动作（这一对 CLICK 就此消耗掉，不会触发单击）
    } else {
        pending_ok = 1; pending_ok_ms = now;
    }
每轮循环：if (pending_ok && now-pending_ok_ms > 350) { pending_ok=0; 执行本屏 OK 单击动作(); }
收到 OK LONG：pending_ok = 0（长按优先）；按 §2.4 执行
任何非 OK 键的 CLICK/LONG：pending_ok = 0（不让上一次 OK 在别的动作后补发）
任何切屏（含 BLE 0x20/0x21、自动锁屏）：pending_ok = 0
```

- **为什么必须全局**：如果只在 READ 延迟，LOCK 上第一击就解锁、第二击落到 CLOCK/SELECT 上
  继续动作（例如连按两下 OK 会解锁并打开书库）；CLOCK 上连按两下会"进书库+打开第一本"。
  全局门让"双击"在任何屏都是**一个**手势，且除 READ 外都是空动作。
- 代价：OK 单击在**所有屏**都有 ~350 ms 延迟。这是复刻 Miaopaper 双击手感的必然代价（M §3.2）。
- PREV/NEXT/MENU/FUNC 不进这个门（没有双击语义），松手即动。
- 测试：`mp_app_key(KEY_OK, KEY_EV_CLICK, t)` 之后必须在 `t+350` 后再次驱动循环（或直接调
  `mp_app_tick(t+351)`）才会看到动作；两次间隔 ≤350 的 CLICK 只能产生"双击"。

## 3. 文案规范

逐字文案在 `docs/COPY_DECK.md`（唯一真源）。规则：

1. **短、直、具体**：一行 ≤ 7 个全角字（112 px），一屏 ≤ 3 行正文。
2. **一句说清**：标题说"这是什么"，正文说"发生了什么/怎么办"。不写两句同义话。
3. **不重复标题**：标题是 `设置`，正文不许再出现"设置"。
4. **不解释常识**：不写"按上下键可以移动"这类。
5. **禁止词**（出现在任何 C 字符串里即验收失败）：
   `请`、`是否`、`确认要`、`操作成功`、`操作失败`、`正在`、`温馨提示`、`注意`。
6. **英文只用于型号/单位**：`Miaopaper`、`E2S`、`GB`、`BOE`、`OED`。不出现 `MENU/OK/FUNC/PREV/NEXT/Settings/Back/Locked`。
7. **错误页只写"什么错 + 怎么办"**：两行，第一行现象，第二行动作。不写原因链、不写错误码。
8. **恢复页 ≤ 3 行**（确认页 2 行、成功页 2 行）。
9. **标点**：中文逗号句号用全角 `，。`；不用 `！`、`~`、`…`；不加书名号（书名直接写）。
10. **数字/单位**：`3分钟`、`10页`、`3.2/7.4GB` 不加空格（原厂 `1分钟`/`5分钟` 同款）。

校验：`tools/check_copy.sh` 扫 `main/*.c` 的所有字符串字面量，命中禁止词或英文键名就返回非 0（§11）。

## 4. 分页契约（与 Miaopaper 逐字节一致）

### 4.1 常量（`mp_page.h` 已冻结）

| 名称 | 值 | 来源 |
|---|---|---|
| 每页行数 | 5 | `ebook.h:87` |
| 单行读取上限 | 80 B | `ebook.h:95` |
| 行宽上限 | 246 | `ebook.h:86`（250 − 2×2） |
| 全角宽 | 16 | `ebook.h:88` |
| 回退窗口 | 400 + 80 = 480 B | `ebook.h:100`、`ebook_layout.h:133-136` |
| 页首栈深 | 16 | `ebook.c:471` |

### 4.2 断行（照抄，不许"优化"）

**ASCII**（`find_line_break_ascii`，`ebook_layout.h:22-38`）：

```
x=0, last_space=-1
for i in 0..len-1:
    if buf[i]=='\n' return i+1
    if buf[i]=='\r' continue
    c = buf[i]; if c<0x20 || c>0x7E: c=' '          # 越界字节按空格
    cw = Dialog_plain_16[c-0x20].xAdvance
    if c==' ': last_space=i
    if x+cw > 246: return (last_space>=0) ? last_space+1 : i
    x += cw
return len
```

**GB2312**（`find_line_break_gb2312`，`ebook_layout.h:40-58`）：

```
x=0, i=0
while i<len:
    if buf[i]=='\n' return i+1
    if buf[i]=='\r': i++; continue
    if buf[i]>=0xA1 && i+1<len && buf[i+1]>=0xA1: cw=16, cb=2
    else: cw=16, cb=1            # 单字节也按全角（A3 区画法）
    if x+cw > 246: return i
    x += cw; i += cb
return len
```

**不许加**：首行缩进、避头尾、CJK/西文混排、连字符断词、省略号。缩进只能来自 TXT 自带的空格/全角空格（M §2.4）。

### 4.3 页边界

```
pos = 起始偏移; line = 0
while line < 5 and pos < book_len:
    to_read = min(80, book_len-pos)
    brk = lb(buf, to_read, 246)          # 只读 to_read 字节
    pos += brk; line++
    if brk >= to_read and to_read < 80: break     # 到文件尾
next = pos
```

`at_end = (next >= book_len)`。**不预读下一行**、不在页尾留空行。`mp_page_measure()` 必须与之一致（用同一份 `mp_lb_*`）。

**读失败**：`mp_page_measure()` 返回 `pos`、`lines=0`；`mp_app` 显示 ERROR 页（`读不到内置存储`），不得死循环重试。

### 4.4 与 Miaopaper 的差异（唯一一处，且不影响页边界）

M 的 ASCII 行高是 **19 px**（`ebook.h:93`），GB2312 是 18（`ebook.h:92`）。需求 3 冻结**阅读区 5 行 × 18 px**，所以本工程两种编码都用 18 px 行距：

- **页边界不变**：分页只由"每页 5 行"和"每行 ≤246 px / ≤80 B"决定，与像素行距无关。同一本书在 Miaopaper 与本工程上 `char_pos` 完全一致。
- 只有纵向位置变了：M 的 ASCII 基线 43+19n（可见 37+19n），本工程 32+18n。差 5 px 起步、逐行收 1 px。
- 视觉后果：ASCII 页比 M 略紧凑（18 px 行高 / cap 12 + 降部 2）；这是"5 行 + 进度条"的代价，写进验收（§11 的像素检查）。

### 4.5 上一页

两条路径，优先级与 M 一致（`ebook.c:911-938`）：

1. **本次会话翻过的页** → `mp_page_hist_pop()`（16 深，满了丢最旧）。
2. **栈空** → `mp_page_prev_start()` 纯布局反推（`ebook_layout.h:128-175`）：
   - `S==0` → 0；
   - `lo = max(0, S-400)`，`win_end = S + min(80, len-S)`，把 `[lo,win_end)` 读进 480 B 窗口；
   - `lo==0`：从 0 正向走页链，返回最后一个起点 `<S` 的页；
   - 否则从 `lo` 到 `S-1` **从小到大**找第一个 `page_end(c)==S` 的候选；
   - 无精确匹配 → 从 `lo` 正向走，返回"包含字节 S−1 的页"。
   - 结果 `>= S` 时视为无上一页（防御，`mp_app` 直接忽略）。

`mp_page_hist_reset()` 的时机：打开书、切书、解锁回阅读、关闭书。

### 4.6 进度

```
pct = at_end ? 100
             : (len==0 ? 0 : (uint8_t)(((uint64)pos*100 + len/2) / len))   # 四舍五入
pct = min(pct, 100)
```

**`at_end` 必须先进 100**：末页起点 `pos < len`，按公式算出来是 97/98 之类；进度条与状态栏
`mid` **共用这一个 `pct`**（同一变量，不许一处算一处另算），否则会出现"条满 100%、字写 97%"。
（`at_end` 由 `mp_page_measure()` 的 `next >= len` 给出。）
- 与 M 一致：进度 = `char_pos / book_len`（M 没有百分比概念，这是新增显示，不改 `char_pos` 语义）。
- `pos` 在保存前必须 `mp_page_clamp(pos, len)`（P §2.2 P1-4）。

### 4.7 编码与绘制分工（冻结）

| 内容 | 编码 | 绘制 |
|---|---|---|
| 界面固定文案（`书库`/`设置`/`关于`/`已锁定`/`没有书`/`重启设备`/`蓝牙 开`…） | **UTF-8 源串** | `text_draw_line()`（经 `mp_ui_text`） |
| 书名（目录 19 B） | **GB2312/ASCII 原始字节** | `mp_text_draw()`（经 `mp_ui_gb_text`） |

**为什么不能统一 UTF-8**：主机（原版 web tool）上传的是**转码后的 GB2312** 字节，目录 `enc` 只有 0/1（`ebook.h:53-54`）；`char_pos` 是**字节偏移**，一旦设备端按 UTF-8 重新解释，页边界与进度就和主机不一致（M §10.1 硬不变量 4）。

### 4.8 `mp_font.c` 的两处必修（否则一切白搭）

1. **P0：GFX 字形 blit 步长错**。`mp_font.c:53-55` 用 `gfx_blit1(..., (w+7)/8)` 按"每行字节"读，而 `fonts/*.h` 是**位连续打包**（P §3.1，已复现：ASCII 重叠成乱码）。修法：在 `mp_font.c` 内写一个按 bit 推进的 `blit_bits()`（每 8 bit 进 1 字节，不按行重置），**不要改** `gfx_blit1()` 的"每行 stride"契约（`mp_font.c:69` 的 HZK 用 stride=2，且 `gfx.h` 是公开契约）。
2. **P1：缺字不许画空心框**。`mp_hz_char()` 现在 `text_hz16_glyph()==NULL` 时画 16×16 空心框，导致 GB2312 模式下的**空格**（`0xA3 0xA0`）显示成方框（本次渲染复现：`书 3` → `书□3`）。Miaopaper 的 `draw_hz_char()` 是 `return`（`ebook.c:641-645`）。改为：`NULL` 就不画，仍前进 16 px。

3. **P0：越界字节的前进宽度必须与断行一致**。现在的三处口径互相打架：
   - `find_line_break_ascii` 把越界字节**替换成空格**再取宽（`ebook_layout.h:29-30`，`Dialog_plain_16` 空格 = **6 px**）；
   - `mp_page.h` 的 `MP_ASCII_MIN_W` 也写 6；
   - 但 `mp_gfx_text()` 对越界字节 `continue`（不前进，`mp_font.c:46-58`），`mp_text_draw()` 的 ASCII 裁剪却按 **8 px** 推进（`mp_font.c:108-111`）。
   只要 ASCII 书里出现 >0x7E 的字节（用户把 UTF-8 文件按 `enc=0` 上传就是这种），分页每字节多 2 px，`char_pos` 与主机不一致，绘制还会叠字。

   冻结成一条规则（三处共用）：

   ```c
   /* mp_font.h 新增，mp_page.c / mp_text_draw / mp_gfx_text 全走它 */
   int mp_gfx_adv(const GFXfont *font, uint8_t c);
   /* c 在 [font->first, font->last] -> glyph[c-first].xAdvance
      否则                          -> glyph[' '-first].xAdvance（两套字体都是 6 / 9） */
   ```

   - `mp_ascii_adv(c)` 就是 `mp_gfx_adv(&Dialog_plain_16, c)`（越界得 6，与 M 一致）；
   - `mp_gfx_text()` 用 `mp_gfx_adv()` 前进，越界字节只前进不画；
   - `mp_text_draw()` 的 ASCII 裁剪也用它（不再写死 8）；
   - **`mp_gfx_width()` / `mp_text_width()` 也必须用它**（现在的 `mp_gfx_width` 对越界字节
     `continue`、不计宽，与绘制差 6 px/字节，选中底线会偏）。
   - 验收（可跑）：`mp_ascii_adv(' ')==6`、`mp_ascii_adv(0x80)==6`、`mp_ascii_adv('M')==14`，
     且对任意串 `mp_ui_text_w(s)` == 实际绘制 ink 的右边界−起点（±1 px，来自 xOffset）。

   验收：`mp_ascii_adv(' ') == 6`、`mp_ascii_adv(0x80) == 6`、`mp_ascii_adv('M') == 14`（本次已在主机上量过 `Dialog_plain_16` 的 `M`/空格）。

## 5. 刷新策略

### 5.0 先看 `display` 的真实行为（否则一定写错）

`display` 不是"post 了就会画"（`display.c:79-189`）：

- **5 s 最小间隔只约束"局刷之后的全刷"**：`gap_ok = !attempted || last_was_full || since >= 5000`
  （`display.c:88-92`）。不满足时，display 任务会先 `vTaskDelay(wait_ms)`（最长 ≈5000 ms）
  **然后**才画（`display.c:284-288`）。所以"翻页（局刷）后马上请求全刷"会让屏幕
  停在**旧内容**上 4–5 s。
- `display_post(fb, FULL)` **不保证立刻出帧**：`want_full = force || !baseline ||
  mode==FULL || family!=1`（`display.c:113`），全刷路径必然走上面的等待。
- `display_post()` 在 `!s_ready` 时**直接 return**（`display.c:367`）——未就绪时什么都不会上屏。
- `stats.frames` **只在刷新成功时自增**（`display.c:209-230`）；失败/未画都不增。
- `display_flush_wait(ms)` 等到"队列空 + 面板 idle"（`display.c:379-395`），**包含**上面那段
  `vTaskDelay`；最长路径 = 5 s 等待 + 全刷 ~1.3 s（BOE）/更久（OED），所以 4000 ms 不够。

### 5.1 冻结的刷新原语

```c
/* 场景切换：立刻出帧；等这一帧真的上屏后再补一次全刷。
 * force_full: 锁屏/错误页传 1（不看"快刷"设置），其余传 0。 */
static void scene_commit(const uint8_t *fb, uint8_t force_full)
{
    display_post(fb, DISPLAY_MODE_AUTO);   /* 通常一次局刷 ~0.45 s（OED 上是一次全刷 ~1.3 s） */
    display_flush_wait(2000);              /* 返回时"我们这一幕（或更新的一帧）"已上屏 */
    if (force_full || !mp_settings.epd_partial_enabled) {
        display_request_full();            /* 此刻 s_dirty==0，走"重画 s_work"分支 */
    }
}

/* 屏内动作（翻页 / 移光标 / 改值）：只局刷，不等。 */
static void page_commit(const uint8_t *fb) { display_post(fb, DISPLAY_MODE_AUTO); }
```

为什么必须是"先 post 再 flush 再 request_full"，而不能用 `frames` 猜：

- `display_post(AUTO)` 走局刷分支（`want_full=false`），**没有 5 s 等待**，立即出帧；
  若基线无效（冷启动/上次失败），display 自己会做全刷（`why=first/recover`），也不会等。
- **`frames` 不能证明"这一帧"已上屏**：post 之前可能已经有一帧在画，它结束时同样让
  `frames++`（`display.c:209-230`、`284-288`）。若这时 `s_dirty` 还是我们刚 post 的新帧，
  `plan_refresh()` 看到 `s_dirty && force` 且 `gap_ok=false` 就会等满 5 s 才画——正是
  §11.8"翻页后立刻按 MENU 不得停在旧页"要防的事。
- `display_flush_wait(t)` 的条件是 **`!s_dirty && !s_busy`**（`display.c:379-395`）：它只在
  队列空、面板 idle 时返回，也就是"我们 post 的那一帧（或更新的一帧）已经画完"。**它没有
  返回值**，所以用"调用它"而不是"读它的结果"来同步。
- flush 之后 `s_dirty==false`，此时 `display_request_full()` 落在"无新帧 + force"分支
  （`display.c:170-178`），重画 `s_work`（同内容）全刷；即使这一刻 `gap_ok=false` 要等 5 s，
  屏幕上已经是新内容，**没有停留/隐私问题**。
- 代价：场景切换会在 app 任务里阻塞最多 2 s（BOE 局刷 ~0.45 s，OED 全刷 ~1.3 s）。可接受：
  切屏是低频用户动作、上传期间不渲染（§5.5）、input 队列 32 条足够吸收这段时间的按键。
- 超时（2 s 没画完）：照样 `request_full()`；最坏情况是补的那次全刷再等 5 s，内容不丢。

### 5.2 决策表

| 场景 | 调用 | 说明 |
|---|---|---|
| 场景切换（任何 ▸屏） | `scene_commit(fb, 0)`（post → flush(2000) → 可选 request_full） | `epd_partial_enabled==1` 时不补全刷（M 的开关语义，M §7.1） |
| 阅读翻页 / 列表移动 / 改值 | `page_commit()` | 局刷；基线无效时 display 自动升全刷 |
| 锁屏 | `scene_commit(fb, 1)`（不看 `epd_partial_enabled`） | 先出锁图，再补全刷 |
| 恢复页 / 错误页 | 见 §5.3 | 恢复页要 frames 判定，可以阻塞 |
| 手动全刷（FUNC） | `display_request_full()` | 由 display 在间隔满足后重画当前帧；UI 不阻塞、不等待 |
| GC | `display_set_gc(mp_gc_interval[idx], READER_GC_IDLE_MS)` | 默认 `{10,20,50,100}` / 45 s 空闲 GC；**boot 时也要调一次**（§10.2） |
| 上传中 | 不刷新 | 与 M 一致（M §7.3：上传期间停时钟刷新/自动锁屏） |

**禁止**：`display_post(fb, FULL)` 直接当"全刷"用（会被 5 s 挡住）；每页全刷；
`DISPLAY_MODE_PARTIAL`（它等价 AUTO，`display.c:113` 的表达式里没有它，P §6.2）。

### 5.3 "真的上屏了吗"——只用 frames 判（仅恢复页）

```c
display_stats_t before, after;
display_get_stats(&before);
display_post(fb, DISPLAY_MODE_AUTO);     /* 先出帧 */
display_flush_wait(8000);                /* 5 s 等待 + 全刷 + 余量；这里可以阻塞 */
display_get_stats(&after);
bool on_screen = after.frames > before.frames;   /* 失败不算 frames（display.c:209-230） */
if (on_screen) display_request_full();           /* 补一次干净全刷，不阻塞 */
```

- `display_flush_wait()` **没有返回值**（`display.h:50`），超时也正常返回（`display.c:390-394`），
  所以只能靠 `frames` 判。
- 8 s = 5 s 最小间隔 + ~3 s 最慢全刷（OED）。仍不够时按"未上屏"处理（失败关闭）。
- 只在 RESTORE 用。锁屏不需要判：锁图已经出帧，补不补全刷只影响残影。

### 5.4 空闲与 GC

- 空闲 GC 保留（45 s，`READER_GC_IDLE_MS`）——这是 e2s_reader 比 M 强的地方（P §6.4），不许关。
- `gc_interval_idx` 改完立即 `display_set_gc()`；开机时也必须应用一次（否则用 `reader_cfg.h` 的
  16 而不是用户设置）。
- OED 面板（`family!=1`）每页都会全刷（`epd.c:539`）。设置页的 `快刷` 开关在 OED 上只影响
  "场景进入"的意图；ABOUT 第 2 页显示 `面板 BOE`/`面板 OED`。**不得**承诺"快刷更快"。

### 5.5 上传/锁屏与刷新互斥

- 上传会话期间 `uploading=1`：跳过重绘、跳过 `power_tick()`（ADC 采样会阻塞 ≥120 ms）、
  跳过自动锁屏。
- 锁屏进入：`scene_commit(fb, 1)`（先出锁图，再补全刷）；之后才允许
  停 BLE 广播/降频（本工程不深睡，见 P §7.4）。
- 恢复页：§5.3 的 `post(AUTO) → flush_wait(8000) → frames 判定 → request_full`，通过后才
  `restore_armed=1`。

## 6. 存储契约

### 6.1 目录与文件（只写 `/sdcard/mp`）

```
/sdcard/mp/
├── catalog.bin     8 B 头 + 8 × 32 B 条目（= 264 B）
├── catalog.tmp     写入中间文件（原子替换用，§6.6）
├── catalog.bak     上一次的有效 catalog（重建前改名）
├── catalog.bad     检测到损坏的 catalog（改名保留，不删）
├── b0.bin … b7.bin 每槽一本书（原始 GB2312/ASCII 字节）
├── font.bin        上传的 HZK16，261696 B（不参与渲染，只为 0x19 兼容）
├── lock.bin        4000 B 锁图 + 0xAA 标志 @0x0FF0（= 4080）
├── progress.bin    8 × 8 B，每槽定长记录（不是 M 的追加环）
└── settings.bin    16 B（"MPS1" + 4 字段 + XOR）
```

- 绝不碰 `/sdcard/books`、`/sdcard/reader`、`/sdcard/bk`、`/sdcard/cache`（P §11#6）。
- 绝不 `format_if_mount_failed`（`storage_sd.c:205-211`）——格式化会毁掉原厂数据与恢复路径。
- `MP_DIR`（`mp_store.c:25`）必须改成 `#ifndef MP_DIR / #define MP_DIR "/sdcard/mp" / #endif`，
  主机模拟器用 `-DMP_DIR="/tmp/mp_sim"` 覆盖；直接 `-D` 一个已无条件 `#define` 的宏会重定义告警。
- **路径约束只属于 `storage_*` API**：`storage.h:5-7` 那句"只允许 /sdcard/books 与 /sdcard/reader"
  约束的是 storage 组件自己的接口；`mp_store` 直接走 VFS（`open/stat/unlink`），平台研究
  §12#44 已明确允许 `/sdcard/mp`。不要为了"合规"把 `mp_store` 改成 `/sdcard/reader/mp`——
  需求 7 与整份 BLE 契约都按 `/sdcard/mp` 写死了。

### 6.2 catalog（与 M §4.1 逐字段一致）

| 偏移 | 长度 | 字段 | 本工程取值 |
|---|---|---|---|
| 0x00 | 4 | magic `"BOOK"` | 同 |
| 0x04 | 1 | ver = 0x01 | 同 |
| 0x05 | 1 | `font_inst` | `mp_store_font_ok()` 的结果（写 1；见 §6.6-6） |
| 0x06 | 1 | `book_cnt` | 恒 0（M 也从不更新） |
| 0x07 | 1 | 0 | 同 |

条目（32 B）：

| 偏移 | 长度 | 字段 | 说明 |
|---|---|---|---|
| 0x00 | 1 | flags | §6.3 |
| 0x01 | 20 | title | 最多 19 B，第 20 B 保持 0 |
| 0x15 | 4 | start | **恒 0**（SD 上一书一文件，M 的 flash 偏移无意义；主机不解析） |
| 0x19 | 4 | len | 声明长度，LE32 |
| 0x1D | 1 | enc | 0=ASCII，1=GB2312 |
| 0x1E | 2 | chars_k（字数除以 1024，LE16） | 0 表示旧目录项 |

### 6.3 槽状态机

```
EMPTY 0xFF --begin--> UPLOADING 0xFE --end(长度校验通过)--> DONE 0xFC
   ^                        |
   +--- abort / 掉电回收 <---+
DONE --delete--> EMPTY（整条清零后写 0xFF）
```

- 只允许 1→0 的位翻转（NOR 语义），SD 上虽无此限制，但**格式保持不变**，因为 BLE `0x15` 会原样回传 flags。
- `MP_FLAG_DELETED=0x00` 只用来标记一次删除中间态；实现上直接回 `EMPTY`。
- `find_free_slot()`：第一个非 DONE 且不等于当前写槽的槽。

### 6.4 进度 / 锁图 / 字体 / 设置

| 对象 | 格式 | 注意 |
|---|---|---|
| 进度 | 8 B：`0x5A, idx, pos[4] LE, 0x00, xor(前 7 B)`，定长 8 槽 | 与 M 的记录格式相同、容器不同（M 是 512 条追加环）。`pos=0` 表示"从头"，不是"无记录"；`load` 失败按 0 处理。**落盘节流**见下 |
| 锁图 | 4000 B + 标志 @0x0FF0 = `0xAA` | 数据 fsync **之后**才写标志；无标志 = 无图 |
| 字库 | 261696 B 裸字模 | **不参与渲染**（渲染用 text 组件内嵌资产）；只为 `0x16–0x18`/`0x19` 兼容 |
| 设置 | 16 B：`"MPS1"`, `ble_enabled`, `sleep_idx`, `partial`, `gc_idx`, 7 B 0, XOR@15 | 默认 `ble=1, sleep=2(60s), partial=0, gc=0(10)`；默认值必须能在**存储失败时**也生效，见 §6.7 |
| 书大小 | 打开书时 `stat(b<idx>.bin)`，`book_len = min(目录声明 len, 真实大小)` | 目录里的 len 是上传时声明的；外部截断/老数据会让 `mp_page_measure` 读到 EOF。`mp_store_book_size()` 返回这个 min 值（§6.6-11） |

**进度落盘策略（冻结）**：翻页只更新 RAM（`char_pos` + `pos_dirty=1`），不 `fsync`；
下列时机才真正写 `progress.bin`：

1. `MENU` 退出阅读 / `NEXT` 长按退出阅读；
2. `0x21` 关书、`0x20` 打开另一本之前；
3. 锁屏（`scene_commit` 之前）；
4. 空闲 ≥ **2 s**（`MP_POS_FLUSH_MS`，在 `mp_app_tick` 里检查）；
5. `esp_restart()` 之前（恢复原厂提交）。

理由：`mp_store.c:621-643` 每次 save 是 `open+lseek+write+fsync`，SD 上一次 fsync 可能几十 ms；
若像 M 那样每翻一页都存（`ebook.c:905`），会挤占 app 任务的按键/BLE 收包预算（P §4.5 的 20 ms 阈值）。
掉电最多丢 2 s 内的一次翻页，可接受。

### 6.5 错误码与 BLE 状态映射

`mp_store` 目前只返回 0/−1（P §2.2 P0-4），必须改成：

### 6.6 `mp_store.c` 必修项（按严重度）

| # | 问题（P §2.2） | 必须改成 |
|---|---|---|
| 1 | `write` 不校验声明长度；`finish` 不 `stat` | `begin` 记 `declared_len`；`write` 拒绝 `off > declared`、`len > declared-off`、32 位溢出、**以及空洞**（`off != written_max` 时拒绝，主机据此发现丢包）；`finish` 必须 `stat().st_size == declared_len`，否则 `abort`，**不得置 DONE** |
| 2 | 读 catalog 失败就 `memset 0xFF` 覆盖现场 | 存在但无效 → `rename catalog.bin → catalog.bad`，再重建；`init` 返回错误让 app 决定 |
| 3 | `flush_catalog` 先 `unlink` 再 `open`（非原子） | 写 `catalog.tmp` + `fsync`，再把旧文件改名 `catalog.bak`，最后 `rename(tmp, catalog.bin)`；FatFs 的 rename 不是 POSIX 原子覆盖，顺序按此固定 |
| 4 | 所有失败压成 −1 | 见 §6.5 的 `mp_err_t` |
| 5 | 与 `storage_remount()` 生命周期冲突 | 提供 `mp_store_sync_close()`；`storage_remount()` 前必调 |
| 6 | 字库标志两套真相 | **只认 `mp_store_font_ok()`**（内嵌字库永远在）；`hdr[5]` 在 `font_finish` 时写 1 只为格式兼容，永不读 |
| 7 | lock/font/progress/settings 无互斥、发布早于 fsync | 全部走同一把递归锁；先 `fsync` 数据，再写标志/catalog |
| 8 | 上传中再次 `begin` 留僵尸槽 | 先 `abort()` 旧槽再开新会话，或返回 `MP_ERR_BUSY` |
| 9 | 进度值不校验 | `save` 侧 `pos=min(pos,len)`；`load` 侧 app 用 `mp_store_book_size()` 截断 |
| 10 | 标题截断可能切断双字节 | 19 B 截断时若第 19 字节是前导字节（0xA1..0xF7）则退到 18 |
| 11 | `book_size` 用目录声明长度，不是文件真实大小（`mp_store.c:474-478`） | 打开书时 `stat()`，`book_len = min(declared, st_size)`；`mp_store_book_size()` 返回该 min；`open` 失败或 `st_size < 16` 视为坏书，回 `0xFF` |
| 12 | 没有容量查询，ABOUT 与 `0x10` 的 `0x02` 都无从判断 | 新增 `mp_store_space(&total,&free)`（§6.5）；`0x10` 用 `free < declared + 64 KB` → `MP_ERR_NO_SPACE`；ABOUT 失败显示 `存储 不可用` |
| 13 | `mp_settings` 零初始化，`mp_store_init` 失败时不 load（`mp_store.c:47/227-241`），BLE 会被静默关闭 | `settings_defaults()` 改名为公开的 `mp_settings_defaults()`；`main.c` 在 `mp_store_init()` **之前**无条件调用（§6.7） |
| 14 | 目录的 20 B 标题**没有独立编码字段**（`mp_book_t` 只有书的 enc），但界面要决定用哪套字形画书名（`mp_ui_row_t.enc` 三选一） | 提供 `mp_store_title_enc(const mp_book_t *b)`：标题里出现任意 `>=0xA1` 的字节 → `MP_STR_GB2312`，否则 `MP_STR_ASCII`；纯 ASCII 书名不许按 GB2312 画（会把每个字母画成全角）。这是 platform.md §2.2 P1-5 的 `ebook.c:700-705` 回退规则的落地 |

### 6.7 挂载失败（需求 7）

- `storage_init()`/`mp_store_init()` 失败 → `mp_app_state.storage_ok=0` → **ERROR 页**：标题 `存储错误`，正文 `读不到内置存储` / `重启设备`，底栏 `[↻]重试` `[▭]返回`。
- **绝不出现"请插卡"**：这是焊死的 SD NAND，用户无法插卡（P §5.2、S §9.4）。原厂连这条文案都没有（只有 `字库丢失…`），我们补一条是刻意改进。
- 存储失败不阻塞启动：按键、BLE、恢复原厂入口都要可用（P §11#8）。
- `mp_store_*` 只在 `storage_ok` 时调用；否则一律走内存里的空视图。
- **设置默认值必须先于一切**：`mp_settings` 是零初始化全局，`mp_store_init()` 失败时不会 load
  （`mp_store.c:227-241`），而 `mp_ble_start()` 会按 `mp_settings.ble_enabled` 决定是否开广播。
  所以 `main.c` 的顺序是：

  ```c
  mp_settings_defaults();      /* ble=1, sleep_idx=2(60s), partial=0, gc=0(10) —— 无条件 */
  storage_init();
  if (storage_ok) mp_store_init();   /* 成功时用磁盘值覆盖 */
  mp_ble_start();              /* 此时 ble_enabled 一定是有效值 */
  ```

  否则"存储坏 → 蓝牙关、休眠 15 s、用户既看不到状态也没法用网页修"——正好是需求 7 的反面。

## 7. BLE 契约

### 7.1 与现有 `ble` 组件的关系（必须先读）

`../e2s_reader/components/ble` 的协议与 Miaopaper **完全不同**：自定义 UUID（`1b0e2a10-…`）、op `0x01..0x41`、`response=req|0x80`、小端、设备名 `E2S-Reader`（`reader_ble.h:4-6`、`ble_proto.h:16-56`）。**原版 web tool 连不上它。**

因此：`mp_ble.c` **不使用** `reader_ble`，直接基于 NimBLE 实现下列服务；`main/CMakeLists.txt` 的 REQUIRES 用 `bt`，**不要**加 `ble`（两套 GATT 同时注册会抢资源，也没有意义）。

### 7.2 GATT / 广播 / MTU

| 用途 | Service | Characteristic | 属性 |
|---|---|---|---|
| 书/字库/锁图/设置/调试 | `0x221F` | `0x331F` | Write + WriteNoRsp + Notify |
| 对时 | `0x1F10` | `0x1F1F` | Write + WriteNoRsp（本工程不发通知） |
| 电池 | `0x180F` | `0x2A19` | Read + Notify（1 B %） |
| 温度 | `0x181A` | `0x2A1F` | Read + Notify（int16 LE，固定 25） |
| 设备信息 | `0x180A` | `0x2A50` | Read（7 B PnP，内容照 `app_att.c:60`） |

- Device Name 特征值 = `"ESL"`（`app_att.c:58`，照抄；web 不读它）。
- **广播/扫描响应名 = `MPP_E2S`（固定 7 字符）**。web 只按 `namePrefix:'MPP'` 过滤（`web:280-285`），**不解析后缀**，所以固定名不影响兼容。理由：P §11#5/§12#43 明确"不要把 MAC 放进 BLE 名/日志、BLE 名固定不带唯一信息"；用 MAC 后缀会让同一张桌子上两台设备都被识别成个人身份。
- 广播数据 = `0x181A` 的 Service Data（AD 长度字节 16 = type 1 + UUID 2 + 载荷 13）：载荷 `MAC6 + temp2 + humi1 + batL1 + batmV2 + counter1`（结构照 `ble.c:58-65`）。**MAC6 六个字节填 0**（字段保留是为了 18 B 结构不变，不填真实地址）；temp 固定 25（E2S 无传感器，M §7.3 同样硬编码），humi 0，counter 每次 +1。
- 安全：`No_Security`，不配对不加密（`ble.c:263`）。**没有认证 ⇒ 锁屏必须自己挡 BLE 的"切屏"命令**（§7.4）。
- 广播间隔 1.0 s（`1600 × 0.625 ms`，`ble.c:266`）；MTU 请求 247（`ble.c:34`，`sdkconfig.defaults` 已有 `CONFIG_BT_NIMBLE_ATT_PREFERRED_MTU=247`）；连接后请求 7.5–10 ms 连接间隔（`ble.c:187-190`）；DLE 251。
- **NimBLE 缓冲必须显式配置**（默认值撑不住 243 B × 24 包的窗口）。`sdkconfig.defaults` 增补：

  ```
  CONFIG_BT_NIMBLE_ACL_BUF_COUNT=24
  CONFIG_BT_NIMBLE_ACL_BUF_SIZE=255
  CONFIG_BT_NIMBLE_HCI_EVT_BUF_SIZE=70
  CONFIG_BT_NIMBLE_MSYS1_BLOCK_COUNT=24
  ```

  验收：1 MB 上传全程 `mp_ble_stats().dropped == 0`（§11.6）。
- **不广播设备身份**：无 SN、无 efuse、无 NVS 字段（P §11#5）。

### 7.3 opcode 全表（0x10–0x44，多字节一律**大端**）

> 路由约束：只有首字节在 `0x10..0x44` 的写才会到应用层（`ble.c:195`）；其它会掉进固件 OTA 分支。本工程不新增 op。
> **长度口径**：`mp_ble_req_t.len` 是 **opcode 之后的字节数**（`mp_ble.h`），而参考实现的 `payload_len` **含 opcode**。两处换算写在本表里，实现时不要照抄参考的比较。

| op | 方向 | 请求 | 应答 | 实现要点 |
|---|---|---|---|---|
| `0x10` 书-开始 | H→D | `[title_len][title…][total u24][enc]` | `[0x10][st][slot]` | **`1 + req->len < 8` → `0xFD`**，等价参考的 `payload_len < 8`（ebook_ble.c:183）。换算：`payload_len = 1 + req->len = title_len + 6`，所以 **`title_len` 必须 ≥ 2**；**单字节书名会被拒**（这是参考行为，不是 bug）。`title_len>19` 截 19 且不切断双字节；`total==0` → `0xFD`；`free < total+64KB` → `0x02`；`st=0x01` 槽满、`0xFE` 忙、`0xFF` 失败 |
| `0x11` 书-数据 | H→D | `[raw 1..243]` | 每累计 256 B：`[0x11][written u24]` | 无会话时回 `written=0`；按绝对偏移写（`off = written`）；**发现空洞（off≠written）立即 abort 并回 `written`**（主机不重传，只能让它失败） |
| `0x12` 书-结束 | H→D | `[]` | `[0x12][st][slot][written u24]` | **必须校验 `written == total`**，不符 → `0xFF` 且 `abort`（不置 DONE）；成功后 `0x00` |
| `0x13` 删书 | H→D | `[idx]` | `[0x13][st]` | 成功后 `mp_progress_save(idx,0)`；**锁屏时回 `0xFF`** |
| `0x14` 书数 | H→D | `[]` | `[0x14][count]` | 只数 DONE |
| `0x15` 查单本 | H→D | `[idx]` | 3 条：`[0x15][idx][0x00][title 0..11]`(15 B) / `[0x15][idx][0x01][title 12..19]`(11 B) / `[0x15][idx][0x02][len u24][enc]`(7 B) | 空槽 `[0x15][idx][0xFF]`；忙 `[0x15][idx][0xFE]`。**三条背靠背发**，不要 `WaitMs(12)`（那是 Telink 通知队列的限制；NimBLE 由 host 排队，同步等待只会白占 app 任务 24 ms） |
| `0x16` 字库-开始 | H→D | `[total u24]` | `[0x16][st]` | 开新会话（type=font） |
| `0x17` 字库-数据 | H→D | `[raw]` | 每 256 B `[0x17][written u24]` | 同 0x11 |
| `0x18` 字库-结束 | H→D | `[]` | `[0x18][st]` | `stat` 必须 == 261696，否则 `0xFF` |
| `0x19` 状态 | H→D | `[]` | `[0x19][font_ok][book_cnt][lock_ok][att_mtu]` | `font_ok = mp_store_font_ok()`（内嵌恒 1）；`lock_ok` 看 0xAA；`book_cnt` **永远是真实 DONE 数**（不要用 0xFF 表示异常——原版 web 会把它显示成"255 本书"）；面板未就绪只进日志与 ABOUT |
| `0x1A` 目录压缩 | H→D | `[]` | `[0x1A][0]` | 回收非 DONE/非当前会话槽 |
| `0x20` 打开书 | H→D | `[idx]` | `[0x20][st]` | 成功 0；失败 `0xFF`；会切屏到 READ；**锁屏时回 `0xFF`，不切屏** |
| `0x21` 关闭书 | H→D | `[]` | `[0x21]` | 保存进度、回 CLOCK、全刷。**锁屏下只 flush 进度并回 `[0x21]`，不切屏、不刷新**（§7.4） |
| `0x30` 锁图-开始 | H→D | `[total u24]`，必须 == 4000 | `[0x30][st]` | 非 4000 → `0xFD`；短包 → `0xFF` |
| `0x31` 锁图-数据 | H→D | `[off u16][data]`，`off+len ≤ 4000` | `[0x31][st]` | 允许乱序/覆盖（M §8.8-7，保留） |
| `0x32` 锁图-结束 | H→D | `[]` | `[0x32][st]` | fsync 后写 `0xAA` |
| `0x33` 回读锁图 | H→D | `[off u16]`（web 只用这种）；**空 = legacy，不支持** | `[0x33][off u16][data dlen]`，`dlen = min(4000-off, 160)`；`off ≥ 4000` → `[0x33][0xFF][0xFF]`；空请求 → `[0x33][0xFE]` | 除最后一块外必须回满 160（web 固定 160 步进 `web:538/551`）；`off=3840` 时 `dlen=160` 正好读到 4000，**不会越界**。前提 **MTU ≥ 166**；无图时也回全 0 块（M §8.8-8 的怪癖，保留） |
| `0x34` 读设置 | H→D | `[]` | `[0x34][ble][sleep_idx][fw_maj][fw_min][fw_patch]` | 版本取 `READER_VERSION_*` |
| `0x35` 写设置 | H→D | `[ble][sleep_idx]` | `[0x35][st]` | `sleep_idx` 越界夹到 2；立即存盘 + `mp_ble_adv()` |
| `0x40` 调试画线 | H→D | `[y u16]`，clamp **≤121** | `[0x40][st][y]` | 画一条全宽横线（FULL）；**进入 DEBUG**（`debug_mode=1`、`debug_until_ms=now+30000`），屏蔽时钟重绘与按键；**锁屏时回 `0xFF`** |
| `0x41` 退出调试 | H→D | `[]` | `[0x41][0]` | 清 `debug_mode`/`debug_until_ms`，回 CLOCK + 全刷；**锁屏时回 `0xFF`** |
| `0x42/0x43/0x44` | H→D | `[]` | `[op][level]` | E2S 没有 PC1：回**充电检测脚 GPIO5** 的电平（1=高，0=低），不驱动引脚【D13】 |
| `0xDD` 对时 | H→D（**0x1F1F**） | `[0xDD][unix32][year u16][month][day][week]` | 无 | 见 §7.5 |

`0x11`/`0x17` 的应答是**累计已写字节**的高水位，不是本包 ack（M §8.4 末注）。

### 7.4 上传状态机 / 流控 / 锁屏白名单 / DEBUG 超时

```
IDLE --0x10--> BOOK(校验 title/total、取槽、建文件)
     --0x16--> FONT(261696)
     --0x30--> LOCK(4000)
任一 ACTIVE --0x11/0x17/0x31--> 写数据
任一 ACTIVE --0x12/0x18/0x32--> 校验 → 发布 → IDLE
任一 ACTIVE --断连 / 60 s 无数据--> abort → IDLE      （0x13 只删已完成槽）
```

**流控（冻结，避免"传不完还转圈"）**：

- 队列 `MP_BLE_REQ_QUEUE = 48`（`mp_ble.h`），≈ 11.7 KB，覆盖 web 的 5832 B 窗口 ×2。
- app 主循环**先抽干**：`while (mp_ble_req_get(&r, 0)) mp_app_ble_req(&r);`，然后才
  `input_get(&ev, 2)`。上传期间不重绘、不采样电量。
- 一次 1 MB 上传的硬指标：`mp_ble_stats().dropped == 0`，且 `0x11` 的 `written` 单调到 total。
- **0x11 没有偏移字段**，设备只能按 `off = written` 顺序写：丢一包不会表现为"off≠written"，
  而是最终 `written < total`。所以兜底只有两处：`0x12` 时 `written == total` 且 `stat` 相符
  （§6.6-1），否则 `0xFF` + abort。`0x31`（锁图）**才有** `off`，可以检测重叠但按原厂允许覆盖。
- **主机不会重传**：web 的 `streamUpload` 只前进、`0x12` 的状态也不检查（`web:782-785`、`web:944-945`，
  M §9.5）。设备侧唯一正确的动作是**立即 abort 并让 `0x12` 回 `0xFF`**，不要让短书变成 DONE。
- 60 s 无数据：用 `mp_app_state.last_pkt_ms`（每收一个 0x11/0x17/0x31 刷新）判，超时 abort 并
  `mp_store_abort`。

**锁屏白名单（安全）**：`mp_app_state.screen == MP_SCREEN_LOCK` 时，`mp_app_ble_req()`：

| op | 锁屏下的行为 |
|---|---|
| `0x14 / 0x15 / 0x19 / 0x33 / 0x34 / 0x35` | 正常处理（只读/设置，不切屏） |
| `0x21` | **只 flush 进度，回 `[0x21]`；不切屏、不刷新**（不能让它把锁屏切回 CLOCK） |
| `0x20 / 0x40 / 0x41 / 0x13` | `MP_ST_FAIL`，不切屏、不点屏 |

理由：GATT 是 No_Security（§7.2），否则任何人靠近都能把锁着的设备变成阅读页/调试画布。

**DEBUG 的退出路径（必须有）**：`0x40` 只把设备留在 DEBUG 30 s（`debug_until_ms`，每次 0x40 续期）。
任一条即退出：`0x41`、**MENU 长按**、30 s 超时。否则 web 调试页一关、蓝牙一断，五键全失效。
DEBUG 期间：不渲染、不响应其它键、不自动锁屏；退出时回 CLOCK + 全刷。

**删除/打开与上传的互斥**：

- `0x13` 删除的是**当前打开的书**：先 `mp_app_flush_progress()`、关书、回 CLOCK（`scene_commit`），
  再删槽；删除期间面板忙按 §5 处理（失败回 `0xFF`）。
- `0x20` 在**上传会话进行中**（`uploading==1`）→ `0xFE`，不切屏。
- `0x20` 打开的书不存在/读失败 → `0xFF`，保持当前屏。

### 7.5 时间同步与走时

```
H→D  [0xDD][unix32 BE][year u16 BE][month][day][week]
```
- `year` 是"十进制年份的十六进制写法"（2026 → `0x07EA`），web 用 `y.toString(16)`（M §8.7）。**不要**按年号解释。
- `week`：1=周一 … 7=周日（`getDay()||7`）。
- `unix` 是**本地时间当 UTC** 的秒数；固件不做时区换算。
- **设备侧走时**（冻结）：收到 0xDD 时记 `time_base_unix = unix`、`time_base_ms = rc_now_ms()`、
  `month/day/week` 用报文里的值。`mp_app_tick()` 每秒用
  `now_unix = time_base_unix + (rc_now_ms()-time_base_ms)/1000` 重算 `hour/min`；
  跨 24:00 时按 `etime.c:44-59` 的规则进位（`min→hour→day→month`，月份天数表 + 闰年），
  `week = (week % 7) + 1`。不重算 `year`（0xDD 每次连接都会重发）。
- 未同步时默认 `2026-01-01 00:00:00`（`unix=1767225600`），`time_valid=1`；上电后
  `time_base_ms` 置 0，`mp_app_tick` 从默认值开始走——**屏幕上不会是永远不动的 00:00**。
- `time_cb` 在 host 任务里回调，只允许置标志；真正的 `mp_app` 更新在 app 任务。
- 同特征写其它首字节（0xE2/0xED/0xF3…）→ **忽略**（不实现调试命令，避免误触发）。

### 7.6 通知

| 通知 | 时机 |
|---|---|
| `0x11`/`0x17` 水位 | 每累计 256 B（`MP_BLE_NOTIFY_STEP`） |
| `0x12/0x18/0x30..0x35` 应答 | 处理完立即 |
| `0x19` | 每次请求；**另在连接后 2 s 主动发一次**（web 连接 2 s 后会自动 `queryStatus`，双保险） |
| `0x15` | 三条背靠背（不插入延时） |
| `0x2A19` | 电量百分比变化 ≥1 或每 60 s |
| `0x2A1F` | 连接后一次（25 → `0x19 0x00`） |
| 广播 Service Data | 每 60 s 或电量变化 |

### 7.7 "原版 web tool 直接可用"的验收点

- 发现：`filters=[{namePrefix:'MPP'}]` 能扫到 `MPP_E2S`。
- 连接：`0x221F/0x331F` 与 `0x1F10/0x1F1F` 都能 `getPrimaryService` + `startNotifications`。
- 连上 2 s 内：`0xDD` 对时、`0x19`、`0x14`、逐槽 `0x15` 全部有回包。
- 上传一本 1 MB 的 txt：`0x10 → 0x11×N → 0x12`，`dropped==0`，`written` 单调到 total。
- 上传后列表出现新书（`0x14` + `0x15`），`0x20` 能打开并在设备上看到第一页。
- `0x33` 请求-应答拿到 4000 B（25 块 × 160 B），**要求 MTU≥166**。Windows Chrome 默认
  MTU 23 且不支持 `requestMTU`，`0x33` 预览在这条链路上不可用（`0x11` 上传仍可用，
  每包 `mtu-4`）；PROTOCOL/验收要写明这一点，不要假装全平台可用。
- `0x34` 读设置、`0x35` 开关蓝牙，设备广播随之开关。
- 锁屏时：`0x20/0x40/0x41/0x13` 全部 `0xFF`，屏幕不变；`0x14/0x19` 正常。

## 8. 恢复原厂

### 8.1 边界（硬）

- 只有 `recovery_stock_probe()` / `recovery_stock_commit()`（`recovery.h:33-37`）能写 otadata。
- 不接收、不下载、不写任何 app 镜像；不做任意槽切换（P §8.1）。
- 写入前必须 `probe` 通过；失败**不写 flash**。
- 提交前保存进度、确认页必须真正上屏；成功后 `esp_restart()`；失败留在失败页。
- 切到原厂是**单向**：要回 mp 只能在原厂运行时把 mp 烧到**当前活动槽**（覆盖该槽原厂镜像）；写另一槽不改变启动选择。文案只写"重启进原厂"，不承诺能回来。

### 8.2 入口

| 屏 | 手势 | 说明 |
|---|---|---|
| SETTINGS | 光标到第 8 项 `恢复原厂固件`，**OK 短按** | 唯一入口（D15）；8 行列表见 COPY_DECK §2.4 |
| ABOUT | MENU → SETTINGS → `恢复原厂固件` | ABOUT 本身只读：OK 短按=回 SETTINGS，OK 长按=锁屏 |

- **面板未就绪时静默拒绝**：`display_ready()==false` 时 `display_post()` 会丢帧（`display.c:367`），
  画什么都不会出现。所以 `restore_enter()` 开头直接 `return`（只 `ESP_LOGW`，并通过 `0x19` 的
  `book_cnt=0xFF` 暴露给主机），**不画 ERROR 页、不写 flash**。
- "刷新失败"这条文案只用于"面板就绪但这一帧没上屏"（§8.3 的 frames 判定失败）。

### 8.3 流程

```c
/* 进入：SETTINGS 第 8 项 + OK 短按 */
void restore_enter(void)
{
    char detail[64];
    if (!display_ready()) { ESP_LOGW(TAG, "restore: panel not ready"); return; }  /* 静默拒绝 */

    recovery_rc_t rc = recovery_stock_probe(detail, sizeof detail);   /* 两个实参！ */
    if (rc != RECOVERY_OK) { mp_app_show_error("无法恢复", rc); return; }

    mp_app_state.prev_screen = MP_SCREEN_SETTINGS;
    mp_app_state.screen = MP_SCREEN_RESTORE;
    mp_app_state.restore_armed = 0;
    mp_app_state.restore_key_ok = 0;

    uint32_t before = frames_now();
    render_restore(0);                       /* 确认页 2 行，hide_hints=0 */
    display_post(fb, DISPLAY_MODE_AUTO);
    display_flush_wait(8000);
    if (frames_now() == before) { mp_app_show_error("刷新失败", -1); return; }
    display_request_full();

    /* 关键：flush 这 8 s 里 input 任务还在往队列里塞 DOWN/LONG。先抽干，再 armed。 */
    key_event_t ev;
    while (input_get(&ev, 0)) { /* 丢弃 */ }
    mp_app_state.restore_armed = 1;
}

/* 按键：armed 之后必须先见到一次 OK DOWN，才接受 OK LONG 提交 */
if (restore_armed && key == KEY_OK && ev == KEY_EV_DOWN)  restore_key_ok = 1;
if (restore_armed && restore_key_ok && key == KEY_OK && ev == KEY_EV_LONG) restore_commit();

void restore_cancel(void) { restore_armed = 0; restore_key_ok = 0; screen = SETTINGS; }
```

```c
/* 提交：只接受 armed && restore_key_ok && OK LONG */
void restore_commit(void)
{
    char detail[64];
    mp_app_flush_progress();                 /* 见 §6.4 的 flush 列表 */
    (void)mp_store_sync_close();             /* best effort */

    recovery_rc_t rc = recovery_stock_commit(detail, sizeof detail);   /* 两个实参！ */
    if (rc == RECOVERY_OK) {
        render_restore_ok();                 /* "已切换" / "3秒后重启"，hide_hints=1 */
        display_post(fb, DISPLAY_MODE_AUTO);
        display_flush_wait(8000);
        vTaskDelay(pdMS_TO_TICKS(3000));
        esp_restart();
    }
    restore_armed = 0;
    restore_key_ok = 0;
    mp_app_show_error("无法恢复", rc);
}
```

- **排队的长按不能提交**：`restore_enter()` 里 `display_flush_wait(8000)` 会阻塞 8 s，期间
  `input` 任务照常入队（`input.h:5-40`）。若不处理，用户在黑屏期按住 OK 产生的 LONG 会在
  `armed=1` 之后被依次处理并直接写 otadata。所以 arming 前 `while (input_get(&ev,0))` 抽干，
  并要求 **armed 之后出现新的 OK DOWN**（`restore_key_ok`）才认 LONG。
- `restore_armed` 的**每一条离开路径都必须置 0**（`restore_key_ok` 同时清）：进入时、MENU 取消、
  提交失败、frames 判定失败、切到 CLOCK/其它屏（含自动锁屏）、BLE 触发 `0x21`。
- 提交前保存进度（§6.4 的 flush 列表）；成功后 `esp_restart()`；**失败绝不重启**。
- `recovery_stock_probe/commit` 的签名是 `(char *detail, size_t detail_len)`（`recovery.h:33/38`），
  rc 是 `RECOVERY_OK / RECOVERY_ERR_NO_STOCK / RECOVERY_ERR_LAYOUT / RECOVERY_ERR_UNSUPPORTED / RECOVERY_ERR_WRITE / RECOVERY_ERR_VERIFY`（`recovery.h:23-30`）。

### 8.4 结果文案

| rc | 标题 | 原因行 | 动作行 |
|---|---|---|---|
| `RECOVERY_ERR_NO_STOCK` | `无法恢复` | `原厂固件不存在` | `先刷原厂固件` |
| `RECOVERY_ERR_LAYOUT` | `无法恢复` | `分区表不匹配` | `先刷原厂固件` |
| `RECOVERY_ERR_UNSUPPORTED` | `无法恢复` | `未开放此功能` | `保持当前固件` |

### 9.6 断言（`--check` 必须全过）

1. **帧合法**：每帧墨点 ∈ [200, 30300]；每帧 32 位像素哈希匹配 `sim/expected.h`
   （25 帧）。
2. **版面不变式**：
   - 状态栏：除 CLOCK 外 y=18 必须是整行黑线；y=19 必须全白；
     CLOCK/y=18 全白；LOCK 不画状态栏；
   - **READ**：`y=110..117` 空白；`(2,119)` 与 `(247,119)` 必须是底线；
     `(2,118)` 是已读；`y=120..121` 空白；
   - **LOCK 有图**：整屏逐像素等于 `epd_temp[y+6]`（bit 1=黑，不反相）；
   - **反色选中条**：SELECT/SETTINGS 选中行 y=行顶、x=7 黑；BOOK_INFO 2×2
     选中按钮顶部、TIME_SET 字段反色框。
3. **字形来源**：`select` 同时出现 GB2312 全角书名与 ASCII 比例宽书名；
   列表没有合成 `返回` 项。
4. **分页**：`sim_store.c` 的连排书喂真实 `mp_page_measure()`；断言
   `lines>0`、`line_w<=246`、末页 `at_end=1`，并由像素哈希锁住内容。
5. **滚动**：`settings` sel=0 → scroll=0；`settings_scroll` sel=5 → scroll=2；
   用 `mp_ui_list_scroll()` 算，不手写。
6. **文案 lint**：`sim/run.sh --check` 调 `tools/check_copy.sh`。
7. **PNG**：`make_contact.py` 生成 250×122 → 3× 图与 25 帧 contact sheet。

### 9.7 实现提示

- PNG 由 `make_contact.py` + Pillow 生成（`--check` 不依赖 Pillow）；像素哈希用
  `rc_crc32_ieee`。C 侧不引 zlib、不调 magick。
- 极性：帧 bit=1 是**白**，PNG 灰度 255；bit=0 → 0。`mp_ui_render` 之后不要反转。
- contact sheet 的排列顺序必须与 §9.4 的列表一致，并在 stdout 打印一行 `order: clock select ...` 便于人工核对。
- **锁图顶部 6 行在设备上不可见**：web 编辑器按 250×128 构图（`web:1070-1083`），设备只显示源
  y=6..127。`lock_img.png` 必须按同一映射生成，DESIGN 与验收里都要写这一条，否则会被当成 bug。
- `lock_img` 的 4000 B 由 `mp_app.c` 的 `static uint8_t s_lock_img[4000]`（.bss）提供；
  `sim` 用同尺寸的 `static` 数组。**不要放栈上**（`mp_ui_state_t` ~800 B + `mp_page_t` ~470 B
  已经不小，`CONFIG_ESP_MAIN_TASK_STACK_SIZE=6144` 会溢出）。

**所有权的三个例外（写清楚，别再猜）**：

1. `main.c` 在任务启动**之前**调 `mp_settings_defaults()` 与 `mp_store_init()`——这是初始化，
   不属于"并发访问 mp_store"；任务起来之后 `mp_store_*` 只由 app 任务调用。
2. `mp_settings` 是全局结构：**只有 app 任务写**；`mp_ble.c` 只读 `ble_enabled`（`mp_ble_start`
   里读一次），`mp_ui.c` 不读。不要为它加锁，也不要让 mp_ble 写。
3. 进度落盘统一走 `mp_app_flush_progress()`（`mp_app.h`），它内部才调 `mp_progress_save()`；
   其它模块不要直接调 `mp_progress_save`。

### 10.2 启动顺序（`main.c`）

```
app_main:
  mp_settings_defaults();         # 无条件！见 §6.7（否则存储坏 -> BLE 被静默关闭）
  display_init();                 # 失败不致命，display_ready()==false
  storage_init();                 # 失败 -> storage_ok=0
  if (storage_ok) mp_store_init();# 失败 -> storage_ok=0（成功时设置已被磁盘值覆盖）
  input_init();
  power_init();
  mp_ble_start();                 # 失败只 log，不阻塞
  mp_app_boot();                  # 读目录、算首帧、display_set_gc(...)
  mp_app_run();                   # 不返回；1 Hz 的 tick 在主循环里做
```

- `mp_store_*` 只在 `storage_ok` 时调用。
- **不单独创建 power 任务**：`power.h:28-30` 写明 `power_tick()` 由 app 任务每秒调用；
  `power_sample()` 内部有 120 ms 阻塞与无锁的 `s_warn/s_last_sample_ms`（`power_policy.c:66-77`），
  跨任务读会撕裂。放在 `mp_app_run()` 的 1 Hz 分支里，上传中跳过。
- `mp_app_boot()` 里**无条件** `display_set_gc(mp_gc_interval[mp_settings.gc_interval_idx],
  READER_GC_IDLE_MS)`：否则开机用的是 `reader_cfg.h` 的 16，而不是用户设置（默认 10）。
- 第一帧：`scene_commit(fb, 1)`（先 AUTO 出帧、再补全刷，§5.1）；冷启动基线无效时 display 自己会全刷。

### 11.4 按键（逐键 × 逐手势）

按 §2.4 的 9 张表逐格手测；重点：

- 五键都在 **CLICK**（松开）上动作；**DOWN 不产生动作**，REPEAT 被忽略。
- **OK 的单击全局延迟 350 ms**（§2.3）：CLOCK 按一下 OK，350 ms 后才进书库；350 ms 内按第二下
  = 双击 → 无动作（不会进书库）。LOCK 上双击 → 不解锁。READ 上双击 → 上一页。
- 任意非 OK 键或切屏都会取消待发的 OK 单击（READ 里 OK 后立刻按 NEXT，只翻一页）。
- 长按语义按 M 恢复：READ 下 **长按 NEXT = 保存并回 CLOCK**（不是连翻）；SELECT 下长按 NEXT = 回 CLOCK；SETTINGS 下长按 PREV = 回 CLOCK；CLOCK 下长按 PREV/NEXT = 进设置/书库。
- OK 长按在 CLOCK/SELECT/READ/SETTINGS/ABOUT 全部 = 锁屏（RESTORE 例外=提交）；READ 下长按 OK 不翻页。
- **恢复页不接受"排队的长按"**：打开确认页后按住 OK 不放（8 s 黑屏期），松手不应提交；
  必须再按一次（DOWN→LONG）才写 otadata（§8.3 的抽干 + `restore_key_ok`）。
- DEBUG（0x40）在 30 s 无 0x40/无连接后自动退出；MENU 长按也能退出（§7.4）。
- OK 在 READ 的单击延迟 ≈350 ms；双击 350 ms 内回上一页。
- MENU 长按从任意屏回 CLOCK（LOCK/RESTORE 除外）。
- FUNC 短按全刷（OED 上本来就全刷，属预期）。
- 底部提示的键集合与该屏矩阵一致（不出现不可用的键）；ABOUT 只有 2 组。

## 12. 未决与风险

1. **按键映射**：GPIO7=MENU、GPIO8=OK 已真机确认；PREV(2)/NEXT(4)/FUNC(6) 仍是推断（P §4.1、`board.h:49-53`）。第一次上机必须先验证，尤其是"长按 NEXT 退出阅读/回时钟"与"长按 PREV 回时钟"这两个 M 的不变量。
2. **`%` 用第二个字体画**（§1.4.3）是渲染验证发现的补丁；如果以后换 8×16 字库，先看它有没有正常的 `%`。
3. **`mp_font.c` 的 P0 blit 修复 + 越界字节前进**（§4.8）是硬前置：不修则 ASCII 乱码/叠字、页边界与主机不一致。模拟器会立刻暴露。
4. **`mp_store.c` 的 14 项修改**（§6.6）里，catalog 原子替换依赖 FatFs rename 语义（P §2.2 P0-3 提醒：不是 POSIX 原子覆盖）。实现时先写死"tmp → 改旧名为 bak → rename tmp"的顺序，并在掉电测试里验。
5. **BLE 与 `reader_ble` 不能共存**（§7.1）。如果后续有人想复用 `ble` 组件，等于放弃 web 兼容。
6. **`0x42/0x43/0x44` 的 PC1 语义**在 E2S 上不存在，本规范用 GPIO5 电平替代；原版 web 不发这三个 op，属调试路径。
7. **时钟源**：E2S 无 RTC，`0xDD` 之前用 2026-01-01 默认值并靠 `rc_now_ms()` 走时；掉电回默认。若将来加 RTC，`mp_time_t` 不用变。
8. **锁图/字体的 fsync 顺序**：`lock_finish` 必须先 `fsync` 再写 `0xAA`（P §2.2 P1-2），否则会出现"标志有效但图不完整"。
9. **自动锁屏与 BLE 连接**：连接期间不自动锁（否则上传一半锁屏）。这是 M 的行为（`app.c:190-208`），本规范沿用。
10. **`docs/COPY_DECK.md` 里每条文案的像素宽**是按 8 px/ASCII、16 px/CJK 算的；改字必须先看宽度列。
11. **NimBLE 缓冲参数是经验值**：`ACL_BUF_COUNT=24 / MSYS1_BLOCK_COUNT=24` 只是 2× 窗口余量，必须用 1 MB 上传压测确认 `dropped==0`；不同 IDF 小版本的默认值会变。
12. **`display_flush_wait(2000)` 是折中**：局刷在 BOE 上 ~0.45 s，OED 上每次全刷 ~1.3 s，2 s 足够；如果将来面板更慢，scene_commit 的"先 AUTO 再补全刷"会退化成"等 5 s 再全刷"（内容不丢，只是没有立即出帧的快刷）。
13. **OK 的 350 ms 全局门**（§2.3）会让所有屏的 OK 单击慢 350 ms——这是 Miaopaper 的手感，也是
    "双击在非 READ 屏=无动作"能成立的前提。若产品要求"确认零延迟"，只能砍掉双击（含 READ 的上一页）。
14. **DEBUG 的 30 s 超时**是经验值：既要不打断 web 调试，又不能让五键永久失效。若调试页会长时间
    停留，需要把续期改成"每次收到 0x40 以外的连接活动也算"。
15. **`0x33` 的空请求不再支持 legacy 流**（回 `[0x33][0xFE]`）；原版 web 只用带 off 的形式
    （`web:538/551`），老工具若发空请求会看到失败，属已知限制。
16. **恢复入口与原任务书的差异**：原任务书写"about/settings 长按确认"，本版按评审把入口收敛为 SETTINGS 第 8 项（OK 短按进入）+ 确认页长按提交；ABOUT 经 MENU→SETTINGS 到达。若要恢复"ABOUT 长按"，必须重新处理"OK 长按一屏之隔从锁屏变不可回退"的问题。
17. **Windows/Chrome 的 `0x33` 预览不可用**（MTU 23 且不协商，160 B 通知塞不下）；上传链路仍可用。PROTOCOL 要写明，否则会被当成设备 bug。
