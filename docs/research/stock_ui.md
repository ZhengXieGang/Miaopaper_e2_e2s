# Paperang E2S 原厂界面考据（stock 1.3.739）

目标：把原厂 250×122 墨水屏的**分区、按键提示、文案、图标/字体风格**还原到可复刻的程度，
作为复刻固件的视觉主参考。用户判断原厂 UI 比 Miaopaper 成熟，本文给出**具体在哪成熟**。

- 固件：`dump/e2s_flash_8mb_r5.bin`（8 MiB，`ota_1` @0x210000 = 原厂 1.3.739，版本串 `1.3.739` @0x213DCC）
- 反汇编源：`tools/fw_ext/seg0_0x3C160020.bin`（DROM）、`tools/fw_ext/seg3_0x42000020.bin`（IROM）、`tools/fw_ext/irom.asm`
- 骨架：`firmware/e2s_re/components/pgui/gui.c`（492 个函数的**地址/名字/日志串**清单，函数体是 TODO）
- 本地已有结论：`firmware/e2s_re/docs/VERSIONS.md`（LVGL 8.2.0 / 字体表 / 显示参数）、`docs/E2S_READER_INVENTORY.md`（硬件、SD、按键）
- 本次**没有**真机、没有原厂界面截图；所有"界面长什么样"都是从代码/字符串/位图**反推**。
  每条都标证据等级：
  - 【A】直接读到（字符串地址、反汇编常量、位图字节）
  - 【B】结构推断（多处一致，但没有运行时确认）
  - 【C】猜测（只作为建议）

复现命令（本文所有地址都可按这两条重跑）：

## 0. 七个问题的一句话答案

| # | 问题 | 答案 | 证据 |
|---|---|---|---|
| 1 | 250×122 怎么分区 | **顶部 18px 状态区（左时钟 / 右电量）+ 中间内容区 + 底部 18px 提示条**（状态区高度是反算，见 §2.4）；内容区三种模板：`234×86@(8,18)`（三格主菜单）、`234×102@(8,5)`（词书/任务页）、`250×122@(0,6)`（整页容器） | §2 |

| 3 | 文案语气 | 全中文、第二人称、`请` 字句为主；短到 1–4 字（`是/否`、`确认`、`继续`、`解锁`、`设置完成`），长句只出现在"解释代价/规则"处（`锁屏展示"…"将会增加约7倍耗电量,是否展示`） | §5 |
| 4 | 图标/字体风格 | 全部 1bpp 无抗锯齿；**没有字重概念**（只有字号 12/16/18/22/30）；图标是 1bpp 索引位图（44×44 主菜单、24×24 设置、18×18 单选、21×10 电量、28×14 `NEW`）；**选中态 = 16×2 短横线**，没有反显框 | §6 |
| 5 | 比 Miaopaper 成熟在哪 | 有**状态区/内容区/提示条三段式**、有图标系统、有字号层级（30/22/16/12）、有页码 `n/m` + 箭头、有 6 档电池图标 + 充电、有插画与结果图（奖杯/咖啡/点赞）、有 `NEW` 角标；Miaopaper 阅读页只有"书名 + 电量百分比文字 + 一条 2px 横线 + 单一 16px 字体"（40px 数码管只出现在独立时钟页） | §7 |

## 2. 屏幕与栅格（问题 1）

### 2.1 物理与逻辑尺寸

| 项 | 值 | 证据 |
|---|---|---|
| 可视 | **250×122**，1bpp | `badapple/main/epd.h:12-13`；`docs/E2S_READER_INVENTORY.md:38` |
| LVGL 画布 | **250×128**，`full_refresh=1`，单缓冲 8000 B | `VERSIONS.md:20`；gui_task 0x4201E5AF–0x4201E5C4（`0x008000FA` / `\|=2`） |
| 面板 RAM | 250 行 × 16 B = 4000 B | 原厂 `heap_caps_malloc(0xfa0,0x400)` @0x4202A9D7 |
| 色彩 | LV_COLOR_DEPTH=1 → 只有黑/白，**没有灰度、没有圆角抗锯齿** | `VERSIONS.md:86` |

> 6 行隐藏在哪：复刻侧 `firmware/e2_e2s_mp/main/mp_font.h` 的注释记的是"画布 250×128、顶部 6 行不可见、`MP_Y()` 减 6"。
> 本文按**可见坐标 y=0..121** 叙述；原厂代码里出现的 y 偏移（如容器 `@(0,6)`）与之吻合【B】。

### 2.2 三段式分区（最重要的一张表）

```
 y=0   ┌──────────────────────────────────────────────┐
       │ 状态区 18px                                    │
       │  时钟 "11:30 星期六"  @(4,7) 12px   [电量 21×10] @右上(0,8) │
 y=18  ├──────────────────────────────────────────────┤
       │                                              │
       │ 内容区（三种模板，见 2.3）                       │
       │                                              │
y=104  ├──────────────────────────────────────────────┤
       │ 提示条 250×18                                  │
       │  左组 x=30              右组 x=144             │
 y=122 └──────────────────────────────────────────────┘
```

| 区块 | 尺寸 / 位置 | 证据（反汇编） |
|---|---|---|
| 状态区容器 | 创建后 `lv_obj_align(TOP_RIGHT, 0, 8)`，内含电量控件 | 0x42020037–0x42020045：`a11=3, a12=0, a13=8` → `lv_obj_align(obj,3,0,8)`；紧接 `call 0x4201fde4` |
| 时钟 | 标签 `set_pos(4,7)`，文本 `%02d:%02d 星期%s`（如 `11:30 星期六`） | 0x42020929–0x42020932：`a11=4, a12=7` → `set_pos`；格式串 0x3C171544；周期定时器常量 `0xEA60`(60000) @0x42020949（`esp_timer` 惯例是 µs，即 60 s 才合理；但常量本身是 60000，**单位未最终确认**） |
| 电量 | 容器尺寸 `(Σ图标宽 + 8, 10)`；电池外壳 21×10 + 电平 21×10 + 正极帽 8×10 + 充电 4×10 | 0x4201FF2A–0x4201FF36：`a11=a3+8, a12=a4` → `set_size`；图标见 §6.4 |
| 内容区（菜单） | **234×86 @(8,18)** | 0x420222C3–0x420222D9：`set_size(234,86)` + `set_pos(8,18)` |
| 内容区（词书/任务） | **234×102 @(8,5)** | 0x420288FD–0x42028911（`set_pos(8,5)`）/0x4202890B（`set_size(234,102)`）；同款见 0x42027405 |
| 内容区（整页容器） | **250×122 @(0,6)**（"设置完成"这类整页） | 0x42024954–0x42024968：`set_pos(0,6)` + `set_size(250,122)` |
| 提示条 | **250×18**，无坐标设置（由调用方摆放/整页刷新） | 0x420200A0：`a11=250, a12=18` → `set_size` |

**算术校验（A）**：`8 + 234 + 8 = 250`，`18 + 86 + 18 = 122` —— 主菜单页正好把 250×122 用满，
这解释了为什么主菜单看起来"最稳"：它严格按 8/18/18 的边距走。

### 2.3 三种内容区模板

1. **宫格页**（主菜单 3 格、设置 3×2）：子项按"对角对齐"摆位，不写绝对坐标。
   - 主菜单：`234×86` 里放 3 个 `78×86`（`78×3=234`），每个是"图标上、文字下、横线最下"。
   - 设置：`83×61` 的瓦片，`align` 依次取 1..6（`TOP_LEFT/TOP_MID/TOP_RIGHT/BOTTOM_LEFT/BOTTOM_MID/BOTTOM_RIGHT`），
     `83×3=249≈250`、`61×2=122`，即 **6 格铺满整屏**（0x420243CC–0x4202441A 连续 6 次 `lv_obj_align(tile,1..6,0,0)`）。
     注意：瓦片的父对象是页面容器（`*(ctx+16)+0`），其尺寸我**没有**直接读到，按 250×122 反算才成立【B】。
2. **整页容器 + 居中**（是/否、提示、引导）：
   - 容器 `250×122 @(0,6)`；标题/主文案 `align(CENTER,0,-8)`，正文 `align(CENTER,0,20)`（0x42024982 / 0x420249B1）。
   - 图标版：40×40 图 `align(CENTER,0,-8)` + 16px 文案 `align(CENTER,0,20)`（0x4202496E–0x420249B1，"设置完成"）。
3. **列表/详情**：`234×102 @(8,5)`，页脚画 `"  %d/%d  "`（0x3C174434）+ 左右箭头位图（0x3C178800 6×10 / 0x3C178820 5×10）。

### 2.4 留白、边距、行距（可直接照抄）

| 量 | 值 | 来源 |
|---|---|---|
| 左右安全边距 | **8 px**（菜单页、词书页一致） | `8+234+8` |
| 状态区高 | **18 px**（推断：`122 − 86 − 18`） | 提示条实测 18（0x420200A0）；菜单内容区实测 86 |
| 提示条高 | **18 px** | 0x420200A0 |
| 图标↔文字间距 | 主菜单 `-29 → -8`（图标底 75、文字底 96，间距 5 px） | 0x42022311 / 0x4202236F |
| 设置瓦片 | 图标底 `-27`、文字底 `-10`、横线底 `-6`（图标 24 高、文字 16 高 → 视觉间隙 3–5 px） | 0x420240A2 / 0x420240C3 / 0x420240E6 |
| 行距（正文） | 16px 字、行高由 `lv_font` line_height=16 决定；多行文案用 `\n` 硬换行 | 字体表 §6.1；串内 `\n` |
| 数字字号 | 计数/页码用 18px 或 22px 纯数字字体（`/0-9:`） | §6.1 |

**推断【B】**：原厂没有做"卡片边框/阴影"，层级完全靠 **留白 + 图标尺寸 + 字号** 建立；
1bpp 下任何圆角/描边都会锯齿，所以设计一律用直角矩形与 1px 线。

### 2.5 例外：单词页没有"固定版式"

单词页（`gui_page_word`，0x42025F8B 起，跨度到 0x420269E0、约 2.6 KB——页面函数里体量最大的一档）**不是模板排版**，
而是把词书文件里自带的布局解释出来——日志把这件事说得很清楚：

- `>>>>>>  line (x0=%d y0=%d) (x1=%d y1=%d) <<<<<<`（0x3C1740C4）
- `line points: %d,%d, %d,%d`（0x3C174130）
- `>>>>>> lable(%d) x=%d,y=%d,font=%d,char num=%d,content=%s  <<<<<<`（0x3C174164）
- 错误分支：`get name prase is too long`（0x3C173FA8）、`word type tab is too long`（0x3C173FDC）、
  `page index err`（0x3C174010）、`word type not find`（0x3C174068）、`unsupport type =%x`（0x3C1741C0）

即：**每个文本块自带 `(x, y, font, 内容)`，还有线段 `(x0,y0)-(x1,y1)`**。
所以"原厂单词页长什么样"取决于词书文件，不存在一张固定的单词页截图。
对复刻的含义：
1. 不要试图 1:1 复刻"单词页版式"——它是内容驱动的（推断：书里带版式是为了不同题型/例句排版）。
2. 我们能复刻的是它**外围的框**：状态区（时钟+电量）、底栏提示（`单击 [◀][▶] 翻页` / `长按 [◀] 返回`）、
   以及 `n/m` 页码 + 箭头；正文区域用我们自己的模板（16px 正文 + 30px 词头 + 22px 计数）。

## 4. 按键提示体系（问题 2）

### 4.1 结论

原厂的提示**不是** `MENU`/`OK` 字样，也**不是**纯箭头。它是
**中文动词 + 键帽小图标**，键帽为独立 1bpp 位图，紧跟在动词后面。

实例（全部来自 0x42020094 这一张 switch 表，地址 0x42020149–0x42020838）：

| type | 左组（x） | 右组（x） | 文案语义 |
|---|---|---|---|
| 0 | `单击 [◀][▶] 选择`（30） | `单击 [○] 确定`（144） | 二选一（**已核实**：0x4202483C 在 `gui_page_set_lock_auto` 0x42024564 内，`a10=0`；同一函数还用 18×18 空心/实心圆 0x3C179EC8/0x3C179F14 + 16×2 下划线，正是"1分钟/5分钟"两选一） |
| 1 | `单击 [◀][▶] 增减`（30） | `单击 [○] 确定`（144） | 数值调节 |
| 2 | `单击 [◀][▶] 翻页`（30） | `长按 [◀] 返回`（144） | 阅读翻页 |
| 3 | `长按 [◀][▶] 3秒取消绑定`（11） | — | 账号解绑（**已核实** 0x42022D85 在 0x42022C40 内，`a10=3`；0x42022CCC 引用 `SN:%s`/`账号绑定`，即 set_account 一系） |
| 4 | `[◀] 返回`（169） | — | 简单返回 |
| 5 | `长按 [◀] 返回`（90） | `已更改为: [✓] 认识`（76） | 单词标记=认识 |
| 6 | `已更改为: [×] 不认识`（70） | `单击 [○] 继续`（88） | 单词标记=不认识 |
| 7 | `单击 [○] 继续`（88） | — | 确认/继续 |
| 8 | `长按 [◀] 返回`（42） | `单击 [○] 继续`（132） | 结算 |
| 9 | `长按 [◀] 返回`（28） | `单击 [○] 再学一组`（122） | 一组学完 |
| 10 | `若要继续学习,请到APP上进行设置` | — | 需要 App 介入（长句，无键帽） |

> 这是原厂 UI 的"统一提示层"：页面只报一个枚举，底栏自己排版。

### 4.2 排版细节【A】

- 条高 18，文字 `align_to(cont, LEFT_MID, x, y)`，**左组 x=30、右组 x=144**（少数长句 11/28/42/70/76/88/90/122/132/169）。

### 5.2 语气分析（可直接指导文案）

**短、直、具体的典型**
- `是` / `否`（1 字）— 二选一不做解释，把解释放在上一行（`锁屏展示"…"将会增加约7倍耗电量,是否展示`）。
- `确认` / `继续` / `返回` / `解锁` / `重来`(无) — 动词单发，不加"请"。
- `电量不足20%,请及时充电` — 给出**阈值**，不是"低电量"。
- `3s,可快速切换同步状态` / `长按〔○〕〔×〕更改标记状态` — 给出**操作 + 结果**。
- `若要继续学习,请到APP上进行设置` — 明确**责任转移**（设备做不到，去 App）。
- `锁屏展示"%s"将会增加约7倍耗电量` — 用**倍数**表达代价，是全套文案里最有说服力的一句。

**风格特征**
1. **中文为主，英文只出现在**：型号/合规（`Model`/`Input`/`CMIIT ID`/`Made in China`）、品牌行（中英双行）、
   `NEW` 角标、`EN` 徽标、`Good!` / `Good Job!` 两句结算语。没有 `Settings`/`OK`/`Back` 这类英文 UI。
2. **第二人称祈使句 + "请"** 是主流；只有紧急句（`电量耗尽,请立即充电`）与错误句（`字库丢失…!!!`）加重。
3. **句尾波浪号** `~` 用于鼓励句，共 **6 处**（`…继续学习吧~`、`…进行学习吧~`、`…巩固一下吧~`、`…巩固哦~`×2、`…明天再来吧~`）；其余不用。`~` 只出现在学习结算类文案里，是一条很稳的"语气分区"规则。
4. **标点不统一**：`若要继续学习,请到…`（半角逗号）vs `若取消绑定，设备上的…`（全角逗号）；
   句号基本不用；感叹号只在 `字库丢失` 出现（3 个 `!!!`）。
5. **有一处错别字**：`字库丢失,请链接手机!!!` 应为"连接"【A】。复刻时建议改成"请连接手机"，
   但如果你要"像原厂"，就保留——这是唯一一处强烈情绪化的文案。
6. **没有**"无卡/存储错误/空间不足"这类文案（见 §9.4），说明原厂把存储当"永远在"的前提。

| 字体层级 | 5 档字号（12/16/18/22/30）+ 专用数字字体 | **阅读页只有 16px**（`Dialog_plain_16` + `HZK16`，`Firmware/src/ebook.h:57-67`；`ebook_layout.h:18` 直接引用 `Dialog_plain_16Glyphs`）；另有**独立时钟页**用 `DSEG14_Classic_Mini_Regular_40`（40px 数码管，`Firmware/src/epd.c:363-373`）——层级只在时钟页出现，阅读页没有 |
| 状态表达 | 6 档电池**图标** + 充电标记 + 时钟 + `n/m` 页码 + 箭头 | 电量是**文字百分比**（`ebook.c:763-775`，充电时加 `+`）；阅读页无时钟、无页码；时钟页左上是 **MAC 地址**（`Firmware/src/epd.c:467`） |
| 时钟 | 常驻状态区（每页都有），12px，`HH:MM 星期X` | 独立"时钟页"：40px 数码管 + 电压/BLE 状态 + 日期（`Firmware/src/epd.c:479-502`），日期用 `9:%c` 这种调试式拼法 |
| 图标 | 58 张 1bpp，成体系（44/24/18/21×10/28×14） | **无图标系统**；只有整幅锁定图（`EB_LOCK_IMG_ADDR`，`Firmware/src/ebook.h:14`）和 `avatar_data.inc` 这类整图 |
| 选中态 | 统一 16×2 短横线，主菜单与设置一致 | 菜单行用行距 + 基线（`EB_MENU_BASELINE`），无选中指示 |
| 按键提示 | 每个页面一条 18px 提示，动词+键帽，13 种组合（§4.1） | 无按键提示（按键行为写死在代码里） |
| 结果/情绪 | 奖杯/咖啡/点赞/`Good!`/`Good Job!`/`恭喜你!` | 无 |
| 留白 | 8/18/18 严格栅格；`8+234+8=250`、`18+86+18=122` | 固定左边距 + 基线网格（`EB_TEXT_MARGIN`），无右边界设计 |
| 弹层 | 226×98 面板 + 独立提示条 | 无弹层 |
| 信息密度 | 主菜单 3 项、设置 6 项/屏 —— 每屏 ≤6 个可点目标 | 一屏可塞十几行文字，密度高但无层级 |

**结论**：原厂的"成熟"不在花哨，而在 **栅格（8/18/18）+ 字号梯度（16 为主）+ 图标系统 + 统一的选中横线 + 每页一条按键提示**。
这五件事构成了一个"不需要解释就能用"的界面；Miaopaper 是可用的阅读器，但它是"排版器"，不是"产品界面"。

## 8. 能复刻什么、受什么限制（问题 6）

**可以 1:1 复刻（不含版权物）**
- 全部坐标/尺寸/栅格/字号梯度（§2、§6.1）；
- 页面清单与层级（§3）、提示条 13 种组合（§4.1）；
- 文案结构与语气（§5.2）；短句可直接沿用（`确认`/`继续`/`返回`/`解锁`/`是`/`否` 这类通用词没有独创性）；
- 选中态"16×2 短横线"、`n/m` 页码 + 箭头、6 档电池图标的**形制**（自己重绘）；
- 90% 的图标语义（书、锁、日历、喇叭、云同步、太阳、奖杯、咖啡、点赞、沙漏、`NEW`）。

**受限制 / 不要搬**
| 对象 | 状态 | 处理建议 |
|---|---|---|
| Zpix TTF（0x480000） | OFL（可自由使用，但它是**独立字体作品**） | 可另装，但**不要**从 dump 里抠出来塞进我们的固件（体积 + 溯源混乱） |
| Alibaba PuHuiTi 子集（0x4DFC44 / 0x4FB7A4） | **商业字体** | 不复刻、不分发；需要同观感就用 OFL 字体（Zpix / 思源黑体 / Noto Sans SC）重生成 |
| 原厂 1bpp 位图字体（12/16/18/22/30） | 由上述中文字体生成，字形版权随原字体 | 用 `lv_font_conv` 从 OFL 字体重新生成；字号/行高/区间照抄（12/16/18/22/30、`/0-9:` 数字子集） |
| 原厂 1bpp 图标（58 张） | 原厂美术 | **建议按同尺寸重绘**（1bpp 图标本质是几何，重绘成本低）；若要直接引用，只用于内部对照 |
| 插画（手持机/整机/`让碎片时间更高效`） | 原厂美术 + 文案 | 重绘；slogan 可换自己的话 |
| 二维码 | LVGL `LV_USE_QRCODE`（MIT，`qrcodegen.c` 在链，`VERSIONS.md:92`） | 可直接用 |
| 字体渲染路径 | UI 文案/标签全部走 5 个位图字体（§6.1），FreeType 只服务单词正文的 TTF 渲染（`VERSIONS.md:72` 的 `lv_ft2/diskio.c`） | 复刻 UI 不要引入 FreeType，纯位图字体即可（能省掉整个 FT 引擎） |

## 9. SDMMC 是不是"内置 SD NAND"（问题 7）

### 9.1 硬件与挂载【A】

| 事实 | 证据 |
|---|---|
| SDMMC 4-bit：CLK=11, CMD=12, D0=13, D1=14, D2=9, D3=10；`width=4`；`flags=1`（内部上拉） | 0x42009BF4–0x42009C20：`s32i 11/12/13/14/9/10` 依次写入 slot 结构，`s8i 4` @+48，`s32i 1` @+52；`docs/E2S_READER_INVENTORY.md:38` |
| **CD / WP 未设置**（沿用 `SDMMC_SLOT_CONFIG_DEFAULT` 的 -1，0x3C164150 模板） | 同上：只覆盖 clk/cmd/d0..d3/width/flags |
| 电源/复位脚 **GPIO34**：挂载前置低 + 延时 50 tick，**整个挂载期间保持低**；卸载才置高 | 0x42009B34–0x42009B76（`gpio_set_level(34,0)` + `delay(50)`）、0x42009CE5（置 1）；`docs/E2S_READER_INVENTORY.md:118-122` |
| 挂载点 `/sdcard`，FATFS，最多重试 3 次 × 500 ms | 0x42009B78 起；`/sdcard` 串 0x3C164104 |
| 失败只打 `========> FATAL: SD card error <========` 然后**继续**起 player/epd/key/ble/gui/datasync | 0x42009AC4 后跳 0x420099DC；`docs/E2S_READER_INVENTORY.md:136`；启动序列表 0x3C163E1C–0x3C163E60 |

### 9.2 内容全部在 SD 上【A】

| 路径 | 用途 |
|---|---|
| `/sdcard/bk/bk0`、`/sdcard/bk/bk1` | 两个词书槽（0x3C165FD4/0x3C165FE4） |
| `/sdcard/book%d`、`/sdcard/book%d/record`、`ctb%d`、`cdb%d_%d`、`crb%d_%d_%04d%02d%02d`、`csb%d` | 词书数据、学习记录、正确/错误计数（0x3C166FCC–0x3C167154） |
| `/sdcard/bk/audio` | 单词/例句音频（0x3C168984） |
| `/sdcard/bk/ttf` | **TTF 字库**（0x3C16A6C4） |
| `/sdcard/cache`、`/sdcard/cache/ota`、`/sdcard/cache/upload.tar`、`sta0`、`sta1` | 缓存、OTA 包、上传包、统计（0x3C167F40/0x3C168E8C/0x3C1677C0/0x3C16A68C） |
| `/sdcard/slogan` | 开机标语资源（0x3C16A6B4） |

NVS 里只有小配置（`bookCfg`、`ttf`、`markIdx0/1`、`helpMode`、`BLBri`、`VoiceVol`…，见 `docs/FLASH_DUMP_FINDINGS.md:74-86`），
**没有**任何书内容。

### 9.3 容量

- 开机挂载成功后打一条 `total=%d free=%d`（0x3C163E70，被 0x420099EF 引用）——即 `f_getfree` 级别的容量探测，**只进日志**。
- 另有 `%dMB %s flash`（0x3C163D98）是内部 flash 容量，也是日志。
- **UI 里没有任何容量/剩余空间显示**（全表 §5.1 无 MB/GB/空间/容量字样）。

### 9.4 用户可见的存储类错误只有一条

`字库丢失,请链接手机!!!`（0x3C1718F0）—— 与 TTF 缺失/加载失败绑定（`VERSIONS.md:72` 的 `ft_diskio` 日志 `TTF font not found` 0x3C16E935、
`init ttf font fs error, clear NVS bit` 0x3C16E9B1）。**没有**"无卡/存储错误/空间不足"界面。

### 9.5 结论

【B，高置信】**原厂把 SDMMC 当"焊死在板上的内置存储"用**：
无 CD/WP、上电由 GPIO34 供电并常驻、开机无条件挂载、全部内容与 OTA 包都在上面、
容量只打日志不显示、失败也继续跑（因为没有它 UI 还能显示"无任务/字库丢失"）。
"SD 卡"在这个产品里只是 **FAT 卷的实现方式**，不是用户可插拔介质。

对复刻的直接含义：
1. 我们的固件也应当"**存储缺失 = 降级但不崩**"，并且**补一条原厂没有的界面**：
   例如 `未检测到存储` / `存储未就绪，请重启`（原厂在这块是空白，属于可以做得更好的地方）。
2. 若要显示容量，参考原厂的克制：不要在主界面显示，放在"设备信息"页一行 `存储 3.2/7.4 GB`。
3. 阅读器若继续用 SPI flash 存书，则**不要**照抄 `/sdcard/book%d/...` 这套命名（那是词卡业务，见 `WORD_MANAGER.md:51-77`）。

## 11. 给复刻固件的落地清单（可直接照抄的数值）

> 目标：在 250×122、1bpp、无灰度的前提下，做出原厂那种"稳"。

**栅格**
- 可见 250×122；画布 250×128（顶部 6 行不用）。
- 边距：左右 8、状态区 18、提示条 18。内容区优先 `234×86 @(8,18)`（三格）或 `234×102 @(8,5)`（列表）。
- 整页提示：图标 40×40 `center(0,-8)` + 16px 文案 `center(0,20)`。

**字体（用 OFL 字体自己生成）**
- 12px（主题默认 / 时钟 / 引导）、16px（正文，占 80%）、18px 与 22px（纯数字 `/0-9:`）、30px（仅首页大标题）。
- 全部 1bpp；不要加粗（做不出）；数字用专用子集，避免中文行高抖动。

**状态区**
- 时钟 `(4,7)`，格式 `HH:MM 星期X`（原厂 `%02d:%02d 星期%s`）。
- 电量右上 `align(TOP_RIGHT,0,8)`，高 10：外壳 21×10 + 6 档电平 21×10 + 正极帽 8×10 +（充电时）4×10 加号；控件宽 = Σ + 8。
- 6 档阈值照抄：`<5` / `5–19` / `20–39` / `40–59` / `60–79` / `80–100`。

**底栏**
- 高 18，左组文字 x=30、右组 x=144；键帽紧跟文字 x+2、y−1；文字 16px，键帽 14×10 / 18×10。
- 组合照 §4.1 抄：`单击 [◀][▶] 翻页`、`长按 [◀] 返回`、`长按 [▶] 解锁` 最常用。

**列表/宫格**
- 3 格：格 78×86（`78×3=234`），图标 44×44 底距 29、文字 16px 底距 8、选中 16×2 底线。
- 6 格：瓦片 83×61（`83×3≈250`、`61×2=122`），图标 24×24 底距 27、文字底距 10、底线底距 6，用 6 个角/边对齐排布。
- 选中：只显示一条 16×2 黑线；**不要**做反显/描边框（1bpp 会糊）。

**弹层**
- 面板 226×98 居中（背景填满 + 1px 边框），图标 24×24，文案 16px，另配一条自己的 18px 提示条。

**文案**
- 沿用原厂的短句骨架（`确认`/`继续`/`返回`/`解锁`/`是`/`否`/`设置完成`），长句只在"解释代价"时出现。
- 建议改进两处：`字库丢失,请链接手机!!!` → `字库丢失\n请连接手机`（改错别字、去掉 `!!!`）；
  补原厂缺失的存储错误文案（`未检测到存储`）。
- 保持"中文为主、英文只用于型号/合规/`NEW`/`EN`"的比例。

**动效**
- 无。1bpp + 全刷 1312 ms / 局刷 454 ms（`docs/E2S_READER_INVENTORY.md:24`）意味着**任何动画都是伪动画**；
  原厂的"层级感"完全靠静态排版，这一点必须继承。

## 12. 未证实 / 风险

1. **没有任何真机截图**：所有布局是从反汇编常量 + 字符串反推的。若原厂在某处用了 LVGL 的 layout（flex/grid）自动排布，
   则我读到的 `align(1..6)` 与最终像素位置可能有偏差（尤其设置页 7 个瓦片只对齐了 6 个，第 7 个 `阅读灯光` 的去向未证实）。
2. **底栏 `align_to` 的 y 参数取自 `type`**（0x42020198 起 `mov.n a14,a2`）。这会让每型整体下移 0–12 px，
   与"18px 条高"矛盾。我按 y=0 叙述；若后续拿到真机截图，请优先核对这一条。
3. **字体归属是推断**：12px≈Zpix、16px≈PuHuiTi 只是从"flash 里正好带这两个 TTF + 尺寸吻合"推的，
   没有字形比对（本次没有成功解析 `lv_font_fmt_txt` 的 sparse cmap，无法逐字渲染）。
4. **`0x420D81A4` / `0x420D81B8` 的 API 名未最终确认**：从调用形态（创建对象 → 设 44×44 图源 → 按头取 w/h → align）
   判为"图元创建 + 设图源"；`0x420C0390` 判为"矩形对象创建"。不影响坐标结论，但影响代码复用的措辞。
5. **页面 ID（47/48/49/50/51/57/59/64/66/70/71/80..88）语义未解**：只知道是按键事件槽，不据此推层级。
6. **第 7 个设置项**（`阅读灯光`，太阳图标 0x3C179C38）建好后没有参与 6 次对齐，可能是条件项/第二页，未证实。
7. **`0x3C1717E0` 里的 `〔〇〕` 与 `0x3C171824` 里的 `〔○〕`** 是两个不同码位（U+3007 / U+25CB），
   我按原样记录；如果复刻字体不含 U+3007，会显示成方框。
